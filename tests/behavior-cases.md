# 行为检查场景

用于维护者审阅和实际任务评估，不是已通过的运行记录。每次挑选与修改相关的案例，说明采用情景推演还是取得实际执行证据。

| 场景 | 最小输入与请求 | 预期行为 |
| --- | --- | --- |
| 已有规范 | 项目已有规则入口、流程和正文；要求优化接续 | 读取相关源并融入缺口，保留有效约束，不生成第二套完整规则 |
| 空项目 | 只有 README；要求建立最小规范 | 补足能执行的入口，不预建状态、决定、日志、合同等完整目录 |
| 过时摘要 | 摘要要求 A；当前用户已选 B，正文支持 B | 核对 B 与其适用范围，按 B 继续；不恢复 A |
| 不可访问的决定 | 摘要声称用户已批准，原会话不可访问 | 不把摘要当新授权；说明缺失依据，继续独立可做部分 |
| 不同版本 | v1 与 v2 各有实际使用者 | 保留各自用途，不因 v2 较新删除 v1 |
| 没有删除授权 | 发现可能被替代的正文，但用户只要求分析 | 返回具体判断与缺失依据，不移动或删除 |
| 并发变化 | 读取文件后用户新增一段，Agent 准备写回 | 重读比较，保留新增内容，合并本轮修改；冲突无法裁决时询问 |
| 只需小改 | 用户只要求改一行文案 | 不误触项目治理，不进行全仓扫描或新建交接文档 |
| 规则正确但没执行 | 原规则明确要求读正文，实际没有读取 | 修读取与执行路径，先修产物，不叠加同义全局规则 |
| 只有只读能力 | 宿主能读但不能写 | 分析并提供具体修订，不声称已经保存 |
| 不共享文件系统 | 远端 Agent 不能读取本机目录 | 明确缺口，按授权共享必要源及版本；不声称 Skill 安装等于上下文同步 |
| 暂停与恢复 | 旧任务暂停，本轮只恢复其中一部分 | 核对原目标与本轮范围，不复活取消内容，不自行放弃其他已确认目标 |
| 验证不足 | 文件与链接检查通过，未在其他客户端执行 | 报告结构检查证据，保留客户端实际调用未验证的状态 |
| 发布隔离 | 维护仓库旁有个人项目和旧 ZIP | 包只使用清单中的公开资源，不收集邻接文件或未知历史包 |

真实反馈进入本表时先去敏并提炼区别性条件。不能为每次措辞差异新增一条案例。
