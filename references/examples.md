# 示例

以下是脱敏的前后对照，用于理解判断顺序与答复形态；具体项目、文件名与措辞按实际任务调整，不要照抄。

## 示例一：摘要说用 A，用户最新选了 B

**输入**

- 交接摘要：“报名页采用方案 A（单页表单）。”
- 用户当前消息：“报名页我后来改成方案 B（分步表单）了，接着往下做。”
- 项目里的报名页需求文档已按 B 写了前两步，没写完第三步。

**处理顺序**

1. 用户最新明确决定在适用范围内优先，摘要只用于定位，不当作授权。
2. 打开需求文档核对：正文已按 B 写，与用户最新说法一致；摘要的 A 已过时。
3. 不恢复 A，也不重写前两步；只补第三步，写入需求文档本身，不另建交接文档。
4. 摘要如是临时消息，不必改动；如在持久文件里且用户授权维护，再按 B 更新。

**答复形态**

```text
已改：需求文档第三步（确认与提交），按分步表单 B 续写。
沿用的决定：报名页采用 B（来自你本轮消息，文档前两步已按 B 写，已核对）。
摘要里的 A 与现状不符，未采用，也未改动摘要文件。
未验证：第三步与前两步的字段命名是否与研发接口一致，需你确认。
需要你决定：无。
```

## 示例二：只有只读权限，且没有删除授权

**输入**

- 用户：“看看 `方案/` 里哪些旧稿可以清掉。”
- 宿主只能读取，不能写入。
- `方案/v1.md` 仍被某个已发布版本引用；`方案/v2-草稿.md` 已被 `方案/v2.md` 吸收，未被引用，也不在 Git 管理中。

**处理顺序**

1. 请求是分析，保持只读；不移动、不删除，也不把“可能可清”当成授权。
2. 对每份材料说明判断依据：是否被引用、是否仍有独立用途、是否已被吸收。
3. 未被 Git 跟踪的草稿，说明恢复方式未知，建议先确认能进入回收站或备份。
4. 不因 v1 较旧就判定可删。

**答复形态**

```text
结论（只读分析，未改动任何文件）：
- v2-草稿.md：内容已被 v2.md 吸收，无引用；但它未被 Git 跟踪，需先确认可恢复方式（回收站或备份）再撤下。
- v1.md：仍被已发布版本引用，不建议清理。
未验证：是否还有仓库外的引用。
需要你决定：是否授权撤下 v2-草稿.md，以及用哪种可恢复方式。
```
