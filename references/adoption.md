# 项目接入

## 从已有材料确定角色

先读用户点名材料与项目已知入口，再定位当前源。不能仅从文件名判断权威，也不要求项目采用指定目录。

| 项目现状 | 适配方式 |
| --- | --- |
| 已有规则入口、导航和当前正文 | 保留职责与路径，把缺口融入对应段落，消除受影响的重复或冲突；常驻主规则只留任务分级、安全底线、信源路由与最低验证，低频专项长流程拆出按需读取 |
| 一个 README 已覆盖必要信息 | 沿用；内容确实过长或职责发生变化时再拆分 |
| 模块导航或 README 堆积大量实验明细 | 首屏保留紧凑的“意图 → 当前维护源”路由表，将逐批实验指标与过程复盘下沉回对应专项目录，避免导航膨胀成第二份正文 |
| 多个工具各维护一份规则 | 比较实际差异，依据用户决定保留共同正文；工具文件仅留必要导入或指向，保护各自仍有效的特定约束 |
| 命令或提示词复述了脚本、配置中的参数 | 阈值、预算、数据结构只留在实际执行它们的脚本或配置中；命令写流程、判断点，并以执行结果为准 |
| 空项目 | 在用户指定或宿主可读取的项目入口写最小约定，不预建整套治理目录 |
| 事实在在线文档或平台 | 写明首选访问通道（如优先检查已安装的专用 CLI 或连接器，不支持时再回退浏览器操作），避免换宿主后反复试错或打断用户扫码登录；本地导出标明来源与时点，不自行接管维护权 |
| 无法读取指定来源 | 说明哪些判断缺少依据，继续不依赖该来源的工作，不以缓存或记忆冒充最新事实 |

如果同一事项的多份正文没有明确替代关系，先查看适用范围、用户决定与引用；不能把同名、较新或更完整当作裁决依据。只有歧义会改变本次结果时才询问。

## 把规则写到会被使用的位置

在现有规则中表达必要行为即可，不要求复制下列固定文本：

> 接任务时从项目入口定位本轮源文件；切换工具或恢复任务后核对其当前内容。新决定在适用范围内更新维护源。修改前核对已有变化；交接说明剩余工作、责任与验证边界。导航和摘要用于定位，完成以实际产物和证据为准。

优先使用随仓库迁移的原生规则入口或最小导入（如项目根 AGENTS.md，以及支持 `@AGENTS.md` 原生导入的 CLAUDE.md），让规则在会话启动时直接生效并兼容 Git worktree 与隔离沙箱；避免仅在用户全局配置用固定本机路径写“请先读取……”，以免快任务多耗读取轮次、被跳过或在分支沙箱中指回旧主目录。命令与脚本优先使用相对仓库根的路径。换平台时只改必要入口，不能顺带修改全局配置、其他 Skills 或外部记忆。

## 接入验收

按本轮需要取得证据，不要求在每个平台上重复完整流程：

1. **配置**：指向真实维护源，路径可访问，规则没有冲突。
2. **读取**：当前会话能通过实际文件读取或宿主提供的加载证据确认入口已进入上下文。无法确认自动加载时，显式要求读取并说明局限。
3. **执行**：在授权范围内完成一个代表任务，核对写入位置、决定沿用及结果。只完成前两项时不宣称实际接续效果已验证。

迁移或覆盖已有规则前比较原内容；保留用户修改和有效约束。已有任务系统的交接与证据功能足够时直接使用，不再建第二套系统。

### 配置自检（可选，在项目根目录执行）

```sh
ls AGENTS.md CLAUDE.md .agents 2>/dev/null          # 入口是否存在（按项目实际入口替换文件名）
grep -n "<规则入口里引用的路径>" AGENTS.md            # 引用的维护源路径是否写在入口中
test -f "<规则入口里引用的路径>" && echo ok          # 引用的路径是否真实存在
```

只能证明“配置”这一步，不能证明会话已读取或任务已执行。维护本 Skill 的仓库另有 `python3 -m unittest discover -s tests -v`，检查分发包结构，不代表行为已验证。
