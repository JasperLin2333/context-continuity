# 项目接入

## 从已有材料确定角色

先读用户点名材料与项目已知入口，再定位当前源。不能仅从文件名判断权威，也不要求项目采用指定目录。

| 项目现状 | 适配方式 |
| --- | --- |
| 已有规则入口、导航和当前正文 | 保留职责与路径，把缺口融入对应段落，消除受影响的重复或冲突 |
| 一个 README 已覆盖必要信息 | 沿用；内容确实过长或职责发生变化时再拆分 |
| 多个工具各维护一份规则 | 比较实际差异，依据用户决定保留共同正文；工具文件仅留必要导入或指向，保护各自仍有效的特定约束 |
| 空项目 | 在用户指定或宿主可读取的项目入口写最小约定，不预建整套治理目录 |
| 事实在在线文档或平台 | 使用有权限的连接读取维护源；本地导出标明其来源与时点，不自行接管维护权 |
| 无法读取指定来源 | 说明哪些判断缺少依据，继续不依赖该来源的工作，不以缓存或记忆冒充最新事实 |

如果同一事项的多份正文没有明确替代关系，先查看适用范围、用户决定与引用；不能把同名、较新或更完整当作裁决依据。只有歧义会改变本次结果时才询问。

## 把规则写到会被使用的位置

在现有规则中表达必要行为即可，不要求复制下列固定文本：

> 接任务时从项目入口定位本轮源文件；切换工具或恢复任务后核对其当前内容。新决定在适用范围内更新维护源。修改前核对已有变化；交接说明剩余工作、责任与验证边界。导航和摘要用于定位，完成以实际产物和证据为准。

路径写成项目内可解析的相对引用，或使用宿主明确支持的定位方式。换平台时只改必要入口，不能顺带修改全局配置、其他 Skills 或外部记忆。

## 接入验收

按本轮需要取得证据，不要求在每个平台上重复完整流程：

1. **配置**：指向真实维护源，路径可访问，规则没有冲突。
2. **读取**：当前会话能通过实际文件读取或宿主提供的加载证据确认入口已进入上下文。无法确认自动加载时，显式要求读取并说明局限。
3. **执行**：在授权范围内完成一个代表任务，核对写入位置、决定沿用及结果。只完成前两项时不宣称实际接续效果已验证。

迁移或覆盖已有规则前比较原内容；保留用户修改和有效约束。已有任务系统的交接与证据功能足够时直接使用，不再建第二套系统。
